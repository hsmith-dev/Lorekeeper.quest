### Synthesis (my inference, built on the sources above)
- Pipeline that the SummaC, R2F and MiniCheck patterns support: split the new entry into atomic claim sentences, then retrieve the top-k canon sentences per claim with pgvector (and entity-anchored if possible), then score sentence-pair NLI and take the max contradiction score. The number of pairs per entry is about claims x k. A k of 5-10 is my unverified estimate and was not benchmarked here.
- Two-stage false-positive control: flag with NLI only above a high contradiction threshold, then ask the local 7B to verify only the flagged pairs and explain them, so the user sees a "possible inconsistency" suggestion, never an automatic block. Temporal and flashback cases ("was dead" vs a flashback) are not handled by any NLI source I found. Treat them as a 7B verification and UX problem (unverified belief).

### Tentative recommendation
- **Primary:** an NLI cross-encoder from the DeBERTa-v3 family at sentence-pair level with SummaC-style aggregation. Start with MoritzLaurer/DeBERTa-v3-large-mnli-fever-anli-ling-wanli (MIT, 0.4B, ANLI 0.70) when accuracy matters. Use cross-encoder/nli-deberta-v3-base (Apache-2.0, 0.2B) as the CPU-light default. Verify flagged pairs with the existing Mistral 7B.
- **Runner-up:** LLM-as-judge with the 7B only. No source here supports small general-instruct 7B reliability; even 70B judges only match a 0.4B fine-tuned checker on LLM-AggreFact.
- **RAM/CPU cost:** about 0.5-1.7 GB for the weights (0.2B-0.4B params in FP32; int8 roughly halves it, per the third-party card). CPU latency is not verified; the best evidence is about 8-30 ms/pair (low confidence, no hardware stated). Benchmark it locally.
- **License:** MIT / Apache-2.0, compatible with GPL plus a commercial license. Avoid Bespoke-MiniCheck-7B (CC BY-NC).

### Tentative recommendation
- **Primary:** an append-only event log (entry_created, session_logged) plus pure rule functions evaluated on each event, with awards stored under a unique (user_id, achievement_id) key so that granting is idempotent. This data model is my unverified belief; no source was retrieved for it.
- Base streaks on sessions, not calendar days, to match real tabletop play cadence. Make them opt-in or hideable, give automatic grace or freezes (Duolingo evidence that slack helps), never use loss or guilt messaging (confirmshaming), never nag (Nagging), and use no countdowns or fake urgency (deceptive.design, EU DFA scope). Celebrate milestones, which Duolingo shows help retention.
- **Runner-up:** achievements only, with no streaks at all.
- **RAM/CPU cost:** negligible (Postgres tables).
- **License:** n/a, no dependencies.
