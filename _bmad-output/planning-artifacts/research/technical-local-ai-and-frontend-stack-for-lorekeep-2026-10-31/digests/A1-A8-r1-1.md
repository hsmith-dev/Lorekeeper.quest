### Tentative recommendation + runner-up + RAM/CPU cost + license
**Recommendation:** use a two-pass extraction.
1. Run the 7B through Ollama with `format`=a flat JSON schema. Keep the schema simple: closed `enum` entity types, no anyOf+properties mixing, no nested $ref, `additionalProperties:false`. Also paste the schema and the existing-entity list into the prompt, and use temperature 0.
2. To protect quality from the documented format-restriction penalty, consider a "reason freely, then format" two-call pattern for relation extraction. Entity typing is classification-like and fine in a single constrained call.
3. Resolve entities in three steps: an alias table first; then a candidate shortlist from rapidfuzz plus sentence-transformers cosine similarity; then LLM adjudication only for borderline cases.

**Runner-up:** use GLiNER v2.1 (Apache-2.0, about 209M params) as a cheap CPU NER pre-pass or fallback, with the LLM doing only relations and resolution.

**RAM/CPU cost:** a 7B Q4 GGUF is roughly 4-5 GB RAM (unverified this run). GLiNER-medium is about 209M params, likely well under 1 GB (unverified). RapidFuzz is negligible. Grammar decoding adds some sampling overhead (llama.cpp tracks known grammar performance issues, #4218).

**Licenses:** Ollama MIT (unverified this run), RapidFuzz MIT, GLiNER code and v2.x weights Apache-2.0. All permit GPL plus commercial use. Avoid GLiNER v0/v1 weights (NC).

### Tentative recommendation + runner-up + RAM/CPU cost + license
**Recommendation:** knowledge-scoped RAG.
1. Store an NPC-to-entry "present_at / knows_of" link (or an array column) and filter retrieval to those entries. Use pgvector >=0.8 with `hnsw.iterative_scan=relaxed_order`, or exact search via a B-tree prefilter. Per-campaign or per-NPC sets are small, so exact search is likely fine.
2. Build the persona prompt on Character Card V2 fields (description, personality, example dialogue).
3. Put a short in-character reminder and a "if it is not in the provided memories, you don't know it — respond in character with uncertainty" rule *after* the history (post_history_instructions). Re-inject it each turn to counter documented drift.
4. Include a few "protective" example exchanges in mes_example in which the NPC feigns ignorance.

**Runner-up:** graph-guided boundary-aware retrieval (RoleRAG-style) over the extracted entity graph from A1.

**RAM/CPU cost:** no extra model is needed. It reuses the 7B and the existing embeddings, so cost is mainly prompt length (CPU prompt-processing time grows with retrieved context; magnitude unverified).

**Licenses:** pgvector is believed to be under the PostgreSQL License (unverified this run). Character Card V2 is a format spec only, so no code dependency is needed.
