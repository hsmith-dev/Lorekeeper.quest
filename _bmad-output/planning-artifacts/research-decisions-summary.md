# Lorekeeper expansion: technical decision summary

Date: 2026-10-31. Source: `research/technical-local-ai-and-frontend-stack-for-lorekeep-2026-10-31/research.md`, where the numbers in brackets are citations.

Constraints: everything local, about 8 GB RAM, CPU-only (GPU optional), and licensing that works for both the GPL and the commercial edition.

| # | Topic | Recommendation | RAM / CPU cost | License | Runner-up |
|---|---|---|---|---|---|
| 1 | Entity/relation extraction | Ollama `format` with a JSON schema [1][2], kept flat (enums, `additionalProperties:false`, no anyOf/$ref [3]). Temp 0, and the schema plus the existing-entity list go in the prompt. For relations, write free text first, then convert to JSON [4]. Resolve entities through an alias table, then a rapidfuzz + embedding top-5 shortlist, then LLM adjudication for borderline matches. Every change goes through the human-review diff. | No new model; reuses the 7B and existing embeddings. Async job on save. | Ollama/llama.cpp MIT; RapidFuzz MIT [8] | GLiNER v2.1 (Apache-2.0, 209M) as a CPU NER pre-pass. Avoid the v0/v1 weights, which are NC [7]. |
| 2 | Contradiction detection | Score claim-to-canon sentence pairs with `cross-encoder/nli-deberta-v3-base` (or xsmall), aggregated SummaC-style [13]. Send only contradictions with p ≥ ~0.9 between sentences that share an entity to the 7B, which verifies them and checks for flashbacks. Show the result as a dismissible flag, never a block. | 71M–200M parameters, about 0.3–0.8 GB; ms per pair on CPU unverified, so benchmark it. OpenVINO/ONNX int8 [17]. | Apache-2.0 [10][11] | The 7B as the only judge (no evidence it is reliable). On a GPU: DeBERTa-v3-large NLI (MIT) [12]. Avoid MiniCheck-7B (NC) [16]. |
| 3 | Live STT | Replace openai-whisper with **faster-whisper int8**. On the same CPU benchmark it is about 4× faster and uses about 37% less RAM [20]. Live mode: a FastAPI WebSocket taking AudioWorklet PCM16 at 16 kHz, with Silero VAD and LocalAgreement-2 (the WhisperLive/WhisperLiveKit pattern [24][25]). Diarization: off by default, run offline after the session with pyannote community-1 [31]. | base int8 is under 1 GB; small int8 about 1.5 GB [20]. Expected 2–4 s caption lag on CPU (unverified). | MIT code and weights [20][26]; pyannote weights CC-BY-4.0 and gated [31] | whisper.cpp (MIT, least RAM, actively released) [21]. Diarization runner-up: sherpa-onnx [35]. |
| 4 | TTS recaps | **Kokoro-82M** (kokoro-onnx or the Kokoro-FastAPI CPU image) as a `tts` sidecar. It has 54 voices, and weighted blending gives genre narrators [36][37]. Avoid XTTS-v2 (CPML, NC) and F5-TTS (NC); Piper is now GPL-3.0 [42][43][47]. |
| 5 | Relationship graph | **Sigma.js 4.0.4 + graphology + @react-sigma/core 6** (WebGL; ForceAtlas2 in a worker; Louvain clusters) [52][53][54] | About 94 KB gz plus graphology; layout runs on the client CPU. | MIT | react-force-graph-2d (MIT, about 58 KB gz, Canvas) [49][51]. Not React Flow, which uses DOM nodes [57]. |
| 6 | PDF/EPUB book | One HTML/CSS (Jinja) source. **WeasyPrint** renders the PDF (margin boxes, `target-counter` table of contents, `string-set` headers) [69]. For large maps, libvips/pyvips `dzsave` cuts a DeepZoom tile set on upload [65]. | About 42 KB gz [60]; tiling is a one-off server CPU cost per upload. | BSD-2 | OpenLayers 10 (BSD-2, built-in Zoomify/pixel projection) [63][64]. **Do not use react-leaflet**: it is Hippocratic-2.1 licensed and v5 requires React 19 [58][59]. |

**Cross-cutting decisions**
1. **License register and CI license check** that fails the commercial build on GPL, AGPL, NC or Hippocratic dependencies.
2. **New models run as sidecars or async Redis jobs** that load lazily. The 7B already takes about half the RAM (unverified), so only STT stays resident during a live session.
3. **Story 0 is a benchmark spike on the 8 GB reference box.** It measures NLI ms per pair, STT lag, Kokoro real-time factor and diarization time, because most CPU figures are unverified.
